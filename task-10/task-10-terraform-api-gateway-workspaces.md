# 🌟 Task 10 - Provision API Gateway and CloudWatch Log Groups using Terraform Workspaces

## 📌 Task Description

The **Nautilus DevOps team** needs to provision multiple API Gateway REST APIs and matching CloudWatch Log Groups across different environments. To achieve environment isolation without duplicating code, the team requires the use of **Terraform Workspaces**. Additionally, resource creation must be audited using `local-exec` provisioners to write logs to the local file system.

**Requirements:**
- Use **Terraform Workspaces** to deploy two environments: `dev` and `prod`.
- Use the **`count`** meta-argument to iterate over a list of API names.
- Create **API Gateways** named:
  - `dev-nautilus-api-1` and `dev-nautilus-api-2` (in `dev` workspace)
  - `prod-nautilus-api-1` and `prod-nautilus-api-2` (in `prod` workspace)
- Create matching **CloudWatch Log Groups** named:
  - `/aws/apigateway/<workspace>-nautilus-api-<index>`
- Use a **`local-exec` provisioner** (via `null_resource`) to log the creation of each resource into two local files:
  - `apigateway.log`
  - `loggroups.log`
- Define a list variable **`KKE_API_NAMES`** in `variables.tf`.
- Supply the values `["nautilus-api-1", "nautilus-api-2"]` via `terraform.tfvars`.
- Export **`kke_api_gateway_names`** and **`kke_log_group_names`** in `outputs.tf`.
- The Terraform working directory is **`/home/bob/terraform`**.
- Verify that `terraform plan` returns **"No changes. Your infrastructure matches the configuration."**

👉 **Your task:** Build a dynamic Terraform configuration that scales across both multiple instances (using `count`) and multiple environments (using `terraform.workspace`).

## 📋 Solution Overview

### 🏗️ Architecture Components
- **`terraform.workspace`:** A built-in Terraform variable representing the currently active workspace. Used in a `locals` block to define an environment prefix (`dev` or `prod`).
- **`count = length(var.KKE_API_NAMES)`:** Allows the creation of multiple resources from a single resource block based on the length of the input list.
- **`null_resource` & `local-exec`:** A resource that doesn't create anything in AWS, but serves as a container to run local shell commands (`echo ... >> file.log`) when its `triggers` map changes.

### 📁 File Structure
```bash

├── variables.tf       # List variable declaration

├── outputs.tf         # Exported names arrays

```

## 🚀 Implementation Steps

### Step 1: Navigate to Working Directory

```bash
cd /home/bob/terraform
```

---

### Step 2: Create Variables Definition File

```bash
cat > variables.tf << 'EOF'
variable "KKE_API_NAMES" {
  description = "List of API Gateway names"
  type        = list(string)
}
EOF
```

---

### Step 3: Create Terraform Variables File

```bash
cat > terraform.tfvars << 'EOF'
KKE_API_NAMES = ["nautilus-api-1", "nautilus-api-2"]
EOF
```

---

### Step 4: Create Main Configuration File

Use `locals` to determine the prefix based on the current workspace.

```bash
cat > main.tf << 'EOF'
locals {
  prefix = terraform.workspace == "prod" ? "prod" : "dev"
}

# Create API Gateways using count
resource "aws_api_gateway_rest_api" "nautilus_api" {
  count = length(var.KKE_API_NAMES)

  name = "${local.prefix}-${var.KKE_API_NAMES[count.index]}"

  tags = {
    Environment = terraform.workspace
  }
}

# Create matching CloudWatch Log Groups
resource "aws_cloudwatch_log_group" "api_logs" {
  count = length(var.KKE_API_NAMES)

  name = "/aws/apigateway/${local.prefix}-${var.KKE_API_NAMES[count.index]}"

  tags = {
    Environment = terraform.workspace
  }
}

# Local-exec provisioner to log creation
resource "null_resource" "log_creation" {
  count = length(var.KKE_API_NAMES)

  depends_on = [aws_api_gateway_rest_api.nautilus_api, aws_cloudwatch_log_group.api_logs]

  triggers = {
    index = count.index
  }

  provisioner "local-exec" {
    command = <<-EOT
      echo "Created API Gateway ${local.prefix}-${var.KKE_API_NAMES[count.index]} in workspace ${terraform.workspace}" >> apigateway.log
      echo "Created Log Group /aws/apigateway/${local.prefix}-${var.KKE_API_NAMES[count.index]} in workspace ${terraform.workspace}" >> loggroups.log
    EOT
  }
}
EOF
```

---

### Step 5: Create Outputs Configuration File

Output the arrays of generated names using a `for` loop construct.

```bash
cat > outputs.tf << 'EOF'
output "kke_api_gateway_names" {
  value = [for api in aws_api_gateway_rest_api.nautilus_api : api.name]
}

output "kke_log_group_names" {
  value = [for lg in aws_cloudwatch_log_group.api_logs : lg.name]
}
EOF
```

## 🔍 Code Analysis

### Terraform Workspaces
Workspaces allow you to maintain multiple independent state files from a single configuration directory. When you run `terraform workspace new dev`, Terraform creates a `terraform.tfstate.d/dev` directory. This is why you can apply the exact same code twice without destroying the `dev` resources when creating the `prod` resources.

### Dynamic Naming with Locals
```hcl
locals {
  prefix = terraform.workspace == "prod" ? "prod" : "dev"
}
```
This ternary operator checks the `terraform.workspace` variable. By tying the resource names to this local prefix, we ensure that API Gateways and Log Groups have globally unique names across environments.

### `count.index`
When `count = length(var.KKE_API_NAMES)` evaluates to `2`, Terraform creates two instances of the resource. `count.index` resolves to `0` for the first instance and `1` for the second, allowing us to dynamically select the corresponding name from the variable array: `var.KKE_API_NAMES[0]` -> `"nautilus-api-1"`.
